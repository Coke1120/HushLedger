# HushLedger v0.1.0-beta.3

## Highlights

- Paste statement text into one entry point, review editable transactions on desktop
  or mobile, and save only explicitly approved rows or a selected batch.
- Confirm uncertain fields and possible duplicates before saving. Approval retries
  are idempotent; undo is available while all affected transactions retain their
  approved versions. Transfers retain the detailed reconciliation flow.
- Suggest categories using only current approved history in the chosen account.
  Matching historic amounts rank suggestions locally and never replace the pasted
  amount. Historical ledger records are not sent to the AI provider.
- Includes native account currencies, opt-in ECB reference observations, encrypted
  saved AI settings, and the compatible stable dependency refresh since beta.2.
- Preserves the pre-redesign main source under `legacy/`, including the source SHA,
  archive checksum and restoration instructions.

## Upgrade and recovery

- This remains a beta release. Back up the intended database and test recovery
  before upgrading. Apply every pending migration through
  `0022_paste_approvals.sql` before starting the updated application.
- Upgrading beta.2 adds migrations 0019–0022. Existing reviewed imports become
  eligible approved history; saved manual or unreviewed transactions do not.
  Editing a transaction invalidates its approval until explicitly reviewed again.
- Configure `AI_SETTINGS_ENCRYPTION_KEY_V1` before saving provider credentials.
  Keep existing Cloudflare Access and alternate-route restrictions in place.
- Portable ledger JSON backups omit operational approval/undo receipts. Restore
  invalidates outstanding receipts and clears approved-history eligibility;
  imported transactions can be explicitly reviewed again. Database backups retain
  these tables. Recovery uses the pre-upgrade backup; no down migration is supplied.
- Node.js: `^22.13.0 || >=24.0.0`; npm: 10 or newer.

## Verification and artifacts

- The local gate covers unit tests, types, lint, Next/OpenNext builds, fresh and
  upgrade migrations, and synthetic Worker/Next integration. The retained browser
  evidence covers desktop/mobile approval, duplicate confirmation, lost-response
  retry, account-scoped history and undo. See
  [verification evidence](../paste-review/README.md).
- Full and production dependency audits report zero vulnerabilities in the
  recorded verification. Dependency compatibility holds and their rationale are
  documented in [the dependency review](../dependency-reviews/2026-10-23.md).
- macOS-specific tests, ARM64 container execution and real-model quality are not
  validated in this cloud environment. No real financial data or provider secrets
  were used in tests.
- Following beta.1/beta.2, this is a source release: GitHub's source ZIP and tarball
  are the expected downloads. There is no configured release-build workflow or
  custom binary/container asset. Main/PR CI runs verification only; no checked-in
  workflow deploys production infrastructure.
